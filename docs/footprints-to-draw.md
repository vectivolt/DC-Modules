# Footprints still to draw

Generated by `calculations/footprint-report.mjs` reasoning, refreshed 2026-09-06.

These are the components whose `Footprint` field names a land pattern that does not exist in the
EasyEDA library yet. They are the **only** source of the `lacks property Footprint` fatal errors
in EasyEDA's schematic DRC (89 on 30kw-acdc, 79 on 30kw-dcdc, 197 on 120kw-dcdc). They are a PCB
library gap, not a connectivity or schematic defect — every one of those sheets reports **0 errors
and 0 warnings** otherwise.

Nothing here has been auto-assigned to a stock footprint. Putting `RES-TH_12R_2W` under a 25 W
wirewound would be fabricated manufacturing data, so the placeholder name stays until a real land
pattern exists.

**Resolved so far** (harvested from EasyEDA's own LCSC catalogue via `component_search`, not
invented): `QA01C` -> `PWRM-TH_QA01C` (LCSC C2757491), closing 62 instances.

**One attempt was rejected, and correctly so.** The HF167F relays were pointed at the catalogue
land `RELAY-TH_HF167F-24-HF` (LCSC C2757422). EasyEDA's DRC refused it:

    [Error] The pin of the component HF167F-80A-M does not correspond to the pad
            (Pin has no corresponding pad: 5, 6, 8 ; Pad has no corresponding pin: 2)

The catalogue part is a plain 4-pad SPST-NO relay; E30 requires the **mirror-contact** variant,
where pins 5/6/8 carry the mirror used for `RELAY_FB_*` readback. Same family name, different
part, different land pattern. Reverted — this is exactly the failure mode the no-auto-assign rule
exists to prevent, and it is worth knowing that group A below needs a pin/pad check per part, not
just a name match.
